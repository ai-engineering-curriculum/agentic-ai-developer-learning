# Labs for mod-106-llm-app-deployment (Shipping an LLM Application)

Guided, step-by-step hands-on sessions. Each lab lists duration, prerequisites, numbered steps with commands or code, expected output, and checkpoints. Unlike the open-ended [exercises](../exercises/), labs are tightly scripted — you read a line, run a command, confirm the result, and move on.

Each lab isolates a *single* move from the module so you can see what that move alone earns before the exercises bundle several together. They can be worked in any order, though each one maps back to the chapter whose claim it is isolating.

- [lab-01 — Pydantic Rejects Before the LLM: Proving the Boundary](lab-01-pydantic-rejects-before-llm.md) *(30–45 min)* — stand up a minimal FastAPI app whose "model" is a module-level counter, then fire 10 labeled probes (empty question, missing field, oversize body, out-of-range `max_steps`, over-long `session_id`) and watch the counter *not* move on any of the eight invalid bodies. Isolates chapter 2's "Pydantic models reject malformed bodies with a 422 before the model is called" claim, with the counter as a mechanical witness.
- [lab-02 — Pre-Check and Post-Charge: Watching the Guardrail Cross the Cap](lab-02-pre-check-and-post-charge.md) *(30–45 min)* — stand up three `/chat` variants that share one `DailySpendGuardrail` and differ only in which of the two `check_and_charge` calls they make (pre-only, post-only, both), then walk each through five requests at a $0.10 cap and $0.04/call to see the `429` fire early under the full pattern, exactly one request late under post-only, and never under pre-only. Isolates chapter 5's three-sentence pre-check/post-charge contract.
- [lab-03 — Does `.env` Make It Into the Image? Proving `.dockerignore` Earns Its Line](lab-03-dockerignore-protects-env.md) *(30–45 min)* — build the same tiny Dockerfile against the same source tree twice, once with `.dockerignore` excluding `.env` and once without, then inspect both images with `docker run cat`, `docker history`, `docker inspect`, and a layer-filesystem `grep` for a sentinel string — proving the obvious tools miss the leak and the one `.dockerignore` line is the difference. Isolates chapter 6's "the single most important line" claim with a fake sentinel key.
